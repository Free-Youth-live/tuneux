=====================================================================
tuneux 插件开发指南（host ABI v1）
=====================================================================
适用版本：tuneux-fx 0.5.x · host ABI v1（已冻结）
权威实现：crates/tuneux-pinx/src/runtime.rs 模块文档（host ABI 的单一事实
来源，本指南与其不一致时以代码为准）。

────────────────────────────────────────────
一、插件系统概览
────────────────────────────────────────────

tuneux-fx 的插件是 WASM 模块（wasmi 解释器执行），运行在能力制沙箱里：

- 能力默认拒绝：文件系统、网络永不注册；插件只能调用宿主注入的少量
  host 函数，且在 manifest 里声明什么才授予什么。
- 控制面 / 数据面分离：插件只做「遥控器」——写效果器参数、注册调色板、
  打日志；真正的音频处理（DSP）由宿主在音频线程执行，皮肤渲染由宿主
  界面层执行。插件永远不接触音频样本与像素。
- 音频线程红线：零插件、零锁、零分配、零 host 调用。

插件的三种入口：
- init(slot)：装载时由宿主调用一次，携带分配到的槽位号（皮肤插件固定为 0）。
- 导出函数：供宿主控制面在需要时调用（如均衡器面板的 set_band）。
- host 函数调用：插件主动调用宿主注入的函数（写参数、注册皮肤、打日志）。

────────────────────────────────────────────
二、开始之前：当前装载限制（如实说明）
────────────────────────────────────────────

当前版本仅装载**官方签名的第一方插件**（均衡器、压缩器、皮肤「午夜蓝」）。
每个插件必须携带有效签名（.sig），验签达到最高信任级才会被装载；
验签失败、文件缺失一律静默跳过、不影响播放器启动。

第三方插件的签名与分发通道**尚未开放**。本指南现阶段用于：
- 了解插件架构与 ABI 的设计（能力制、沙箱、槽位机制）；
- 为将来的第三方开发提前熟悉接口；
- 跟随源码自行构建实验（见第九节末注）。

开放第三方装载时将随版本公告说明签名申请方式。

────────────────────────────────────────────
三、插件三件套与目录
────────────────────────────────────────────

每个插件由三个同名文件组成，放在 plugins/ 目录下。皮肤插件的文件名
必须以「皮肤-」开头（皮肤命名规则，加载器据此识别并全部扫描）；
多份皮肤共存，用户在「设置 → 皮肤配色…」菜单里切换。例如：

  plugins/
  ├── 皮肤-Norton蓝.wasm       插件本体（WASM 模块，可由 WAT 文本构建）
  ├── 皮肤-Norton蓝.manifest   能力清单（纯文本，见第四节）
  ├── 皮肤-Norton蓝.sig        签名（64 字节；当前仅官方可签发，见第二节）
  ├── 皮肤-午夜蓝.wasm / .manifest / .sig
  ├── equalizer.wasm / .manifest / .sig      （效果器插件）
  └── compressor.wasm / .manifest / .sig

目录解析顺序：
1. 可执行文件同目录的 plugins/（随包分发位置，优先）；
2. 数据目录下的 plugins/（程序目录不可写时的回退位置，与各平台
   配置/数据目录同规则）。

装载时机：启动时扫描 plugins/；均衡器 / 压缩器面板内可按 u 重载。
装载结果（成功 / 验签失败 / 能力授予集）写入插件核查日志
tuneux-fx-plugins.log（数据目录下，追加式）。

────────────────────────────────────────────
四、能力清单（manifest）
────────────────────────────────────────────

manifest 是纯文本：每行一个能力短名，# 开头为注释，空行忽略，
重复条目自动去重。**未知短名会导致整个 manifest 解析失败**（插件不装载）。

能力短名一览（v1）：

  短名            含义                                     当前状态
  audio_dsp       音频效果器参数控制（均衡器 / 压缩器槽位写入）  已开放（第一方）
  theme           注册调色板（皮肤供色）                      已开放（第一方）
  audio_play      音频播放控制                               预留，未接线
  metadata_read   读取曲目元数据                             预留，未接线
  ui_write        向界面写入有限文本                          预留，未接线
  network         网络请求（宿主代发）                        永久默认拒绝

示例（皮肤插件，skin.manifest）：

  # 只声明需要的能力；多声明的能力不会被授予
  theme

────────────────────────────────────────────
五、host ABI 函数详解（v1 + v2 增补）
────────────────────────────────────────────

宿主在 "host" 命名空间注入的函数。返回值约定：0 = 成功，
1 = 槽位错误，2 = 参数号越界，3 = 内存 / 编码错误。

【eq_set(slot: i32, band: i32, gain_db: f32) -> i32】
  写均衡器某段增益（单位 dB，钳制 ±12）。
  slot = init 时分配到的槽位号；band = 段号，范围 [0, 10)。
  需要能力：audio_dsp。

【compressor_set(slot: i32, param: i32, value: f32) -> i32】
  写压缩器参数。param 编号：
    0 = 阈值    1 = 压缩比    2 = 启动时间
    3 = 释放时间  4 = 补偿增益
  需要能力：audio_dsp。

【log(ptr: i32, len: i32) -> i32】
  把插件线性内存 [ptr, ptr+len) 的一段 UTF-8 追加到宿主日志。
  len 上限 64 KiB（超限拒绝，防内存攻击）。无需声明能力。

【theme_register(ptr: i32, len: i32) -> i32】
  把线性内存里的一份调色板文本（格式见第七节）注册给宿主；
  宿主读原始字节后交界面层解析。len 上限 8 KiB。
  需要能力：theme。通常在 init 里调用一次。

【meter_len() -> i32】（ABI v2 增补）
  返回当前实时频谱段数（0 = 无数据）。需要能力：meter_read。

【meter_read(ptr: i32, len: i32) -> i32】（ABI v2 增补）
  把 min(len, 段数) 个 f32（小端字节）写入插件线性内存 [ptr, …)；
  返回实际写入段数。数据 = 宿主注入的最新频谱快照（归一化 0.0-1.0）。
  需要能力：meter_read。在 tick 导出里周期调用（见第八节）。

────────────────────────────────────────────
六、效果器插件开发（含完整示例）
────────────────────────────────────────────

【槽位机制】
效果器不直接处理音频，而是绑定一个「槽位」：宿主为每个效果器插件分配
独立槽位号（均衡器与压缩器各 8 个槽，同类型可叠加串联，按槽位号升序
在音频线程依次执行），init(slot) 把槽位号交给插件；插件此后所有
参数写入都必须携带这个 slot。

【最小示例：10 段均衡器（直通），equalizer.wat】

  (module
    (import "host" "eq_set" (func $eq_set (param i32 i32 f32) (result i32)))
    (import "host" "log" (func $log (param i32 i32) (result i32)))
    (memory (export "memory") 1)
    (data (i32.const 0) "tuneux-eq")
    ;; init(slot)：写 10 段 0 dB（直通）到被分配的槽位，打一条加载日志。
    (func (export "init") (param $slot i32) (result i32)
      (call $eq_set (local.get $slot) (i32.const 0) (f32.const 0.0)) drop
      ;; ……段 1 至 8 同样写 0.0……
      (call $eq_set (local.get $slot) (i32.const 9) (f32.const 0.0)) drop
      (call $log (i32.const 0) (i32.const 9)) drop
      (i32.const 0))
    ;; set_band(slot, band, gain_db)：控制面转发——宿主界面调整时调用。
    (func (export "set_band") (param i32 i32 f32) (result i32)
      (call $eq_set (local.get 0) (local.get 1) (local.get 2)))
  )

配套 manifest：

  audio_dsp

要点：
- 写参数立即生效（宿主经无锁通道把参数推进音频线程），插件无需也不应
  维护自己的音频状态。
- 增益等数值由宿主钳制到安全范围，插件传入非法值不会损坏音频。

────────────────────────────────────────────
七、皮肤插件开发（含完整示例与调色板格式）
────────────────────────────────────────────

皮肤插件只做一件事：init 时经 theme_register 注册一份**调色板文本**。
插件只提供颜色、不接触渲染；宿主按调色板绘制界面。

【调色板文本格式】
每行一条「键=值」，# 开头注释、空行忽略，键与值两侧空白忽略。
全部键可省略——缺失字段回落终端原生配色；未知键与非法值宽松忽略，
不会导致加载失败。全文没有任何「键=值」行才视为「未注册皮肤」。

  键            含义
  name          皮肤显示名（皮肤选择器清单里显示；缺省用文件名去「皮肤-」前缀）
  bg            屏幕底色
  fg            正文颜色
  border        边框颜色
  border_type   边框线型：double = 双线，其他值 = 单线
  menu_bg       菜单栏底色
  menu_fg       菜单栏字色
  fkey_num      功能键号颜色（none = 不着色、暗淡纯文本）
  passthrough   语义色：原样直通指示（技术参数行亮色）
  resample      语义色：重采样降级指示（技术参数行暗色）
  bar_fg        频谱柱体颜色（缺省亮绿）
  peak_fg       频谱峰值帽（白帽）颜色（缺省白）
  grid_fg       频谱基线 / 网格颜色（缺省深灰）
  level_low     电平表低档（<60%）颜色（缺省绿）
  level_mid     电平表中档（60–85%）颜色（缺省黄）
  level_high    电平表高档（≥85%）颜色（缺省红）
  band_low      三桶能量低频桶颜色（缺省回落 bar_fg）
  band_mid      三桶能量中频桶颜色（缺省回落 bar_fg）
  band_high     三桶能量高频桶颜色（缺省回落 bar_fg）
  bar_style     频谱柱字符风格：matrix（细字符雨，默认）/ blocks（块字符）
                / ascii（#*= 复古）/ hanzi（汉字柱，2 列宽、横向分辨率减半）

字符风格说明：字符集宿主内置并逐字符过宽度校验（皮肤只选风格、不自由
输入字符）——hanzi 为 2 列汉字柱（池取李白《将进酒》摘句）、横向分辨率
减半；选择风格后频谱、电平表、示波器三者同步切换。

颜色值三种写法：
- #rrggbb    十六进制（恰好 6 位 ASCII，如 #0d1321）
- none       沿用终端默认色
- 具名色     white / black / gray / grey / darkgray / dark_gray /
             red / green / blue / yellow / cyan / magenta

语义色纪律：passthrough 与 resample 承载「直通 / 降级」信息而非装饰——
任何皮肤都必须让两者在所选底色上清晰可辨；非法值会回落默认（白 / 深灰），
语义不随皮肤丢失。

【完整示例：皮肤「午夜蓝」，皮肤-午夜蓝.wat】

  (module
    (import "host" "theme_register"
      (func $theme_register (param i32 i32) (result i32)))
    (memory (export "memory") 1)
    (data (i32.const 0)
      "name=午夜蓝\nbg=#0d1321\nfg=#c8c8c8\nborder=#5f87af\nborder_type=double\nmenu_bg=#3a4a5f\nmenu_fg=#e8e8e8\nfkey_num=#ffb000\npassthrough=#ffffff\nresample=#5f5f5f")
    ;; init(slot)：注册调色板。slot 参数忽略（皮肤不占效果器槽位）。
    ;; 注意第二个参数是文本的字节长度，须与 data 段实际长度一致。
    (func (export "init") (param $slot i32) (result i32)
      (call $theme_register (i32.const 0) (i32.const 156)) drop
      (i32.const 0))
  )

配套 manifest：

  theme

────────────────────────────────────────────
八、可视化插件开发（tick + meter_read + 画面约定）
────────────────────────────────────────────

可视化面板插件（文件名以「可视化-」开头）在插件面板（v 键循环到「插件」
态）里显示自己产出的字符画面。机制三件：

【周期调用 tick】插件可选导出 `tick() -> i32`——宿主每帧调用（面板可见
且正在播放时）；未导出 tick 的插件不被周期调用。

【读频谱】tick 里用 meter_len / meter_read 取宿主注入的最新频谱快照
（f32 数组，归一化 0.0-1.0）。

【画面约定】tick 里把字符画写进线性内存约定区：
  [0, 4)         u32 小端 = 画面字节长度
  [1024..1024+n) UTF-8 文本（行以 \n 分隔）
宿主在 tick 后读回并贴上插件面板。插件只产文本、不碰渲染。

最小骨架见仓库示例 assets/可视化-能量条.wat（有完整注释）：读 256 段
频谱 → 低 / 中 / 高三桶取最大值 → 三行块字符条。

manifest 只需一行：meter_read

────────────────────────────────────────────
九、调试与日志
────────────────────────────────────────────

- 插件内用 log() 打文本日志，可在宿主日志中查看；
- 每次装载的信任级、授予的能力集都记录在数据目录的
  tuneux-fx-plugins.log，装载失败先看它；
- 皮肤解析宽松：改调色板后不必改代码，重载或重启即可预览；
  某项显示不对时，先检查该键的拼写与颜色值是否合法。

────────────────────────────────────────────
十、构建与装载步骤
────────────────────────────────────────────

1. 编写 .wat 源文件（或用任意可产出 WASM 的工具链）；
2. 用仓库自带的生成工具构建（内部走 wat crate）：
   cargo run --example gen_eq_plugin -p tuneux-pinx -- 皮肤-我的皮肤；
   （效果器插件同名用法：-- equalizer / -- compressor）
3. 编写同名 .manifest（只声明用到的能力；皮肤固定 theme）；
4. 签名生成 .sig——当前仅官方流程可签发（见第二节）；
5. 三件套放入 plugins/ 目录，重启或面板内按 u 重载；
6. 查看 tuneux-fx-plugins.log 确认装载结果。

注：跟随源码的开发者可在本地构建仓库后，用
crates/tuneux-pinx/examples/ 下的示例工具自行走通「构建 → 签名 →
装载」全流程做实验；分发给他人使用仍受第二节限制约束。

────────────────────────────────────────────
十一、兼容承诺
────────────────────────────────────────────

- host ABI v1 已冻结：已冻结的函数签名、返回码约定、能力短名在 v1 内
  不被破坏；新增能力以新增函数 / 新增短名方式追加，不改既有语义。
- 本指南随 ABI 版本演进；函数级细节以 crates/tuneux-pinx/src/runtime.rs
  模块文档为最终依据。
